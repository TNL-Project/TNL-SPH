# Ghost boundary particles at multiresolution interfaces — design

Status: implemented. Variant B (copy-from-neighbor geometry, commit 0d1f382) was verified
and then removed; the ghost geometry now always comes from a pre-generated own-resolution
lattice, with two selectable per-step update methods (`interpolation`, `direct-from-source`).
Scope: `SolverMultiSetBlockMultiresolution` cases (2D 2-zone / 3-zone dam break, 3D dam break)

## 1. Problem

The multiresolution decomposition partitions the wall boundary over subdomains: each
subdomain owns the wall segments inside its box at its own resolution, and
`MultiresolutionBoundary` patches represent only the **neighboring fluid** (buffer
particles). A fluid particle near a subdomain corner (e.g. left-bottom edge of the L1/L2
zone) reaches with its kernel past the subdomain edge, but the wall continuing on the
other side belongs to the neighbor's boundary set and is invisible to it. Result:
one-sided wall support at the seam — asymmetric wall force, density dip/leak and corner
artifacts. The missing interaction is the **neighbor's wall** in the interface band.

Goal: make each fluid set interact with the complete wall next to its subdomain, while
keeping the structure clean and the model kernels untouched.

## 2. Update methods

The ghost **geometry** is single-sourced: an own-resolution wall lattice generated by the
init script (`generate_ghost_band_boundaries` in `init_multi_resolution.py`) and shipped
as one VTK file per directed interface (`boundary-ghost-buffer-<p>.vtk`). What the config
selects per run is only *who manufactures the ghost wall values* each step, via the
`boundary-ghost-method` entry (`interpolation` is the default):

| stage | `interpolation` (default) | `direct-from-source` |
|---|---|---|
| ghost values (rho, gamma) | MFD interpolation over the **source boundary's** fresh values (same machinery and support thresholds as `MultiresolutionBoundary::interpolateVariables`); slots without reliable support keep their last values | standard boundary-fluid pair terms accumulated over the **source fluid** (`Σ W·m`, `Σ W·m/ρ`; mass doubled for conservative BCs) followed by the model's own boundary finalization (gamma renormalization with the `rho0` floor for consistent BCs, raw sums for conservative BCs) |
| value provenance | neighboring subdomain's *processed wall state* | neighboring subdomain's *fluid state*, evaluated through the model's wall interaction |
| empty support | keep previous value (stale-but-stable wall value) | zero sums → dry-wall values (`rho = 0`, `gamma = 0`), identical to a regular dry wall slot |

Variant B (ghost geometry copied once from the neighbor's boundary particles in the band,
values copied per step) delivered the first working pipeline and was verified (2D t = 1.0
and 3D t = 2.0, commits 0d1f382 + 2535a21). It was **removed** once the own-resolution
geometry was verified: a single geometry source keeps one init path, one resolution
convention, and no runtime band selection. Interfaces without a ghost file have no ghost
particles (currently the 3D example, whose init script does not emit ghost files yet).

## 3. Geometry and band definition

- Ghost band = the **buffer band** of the directed interface: cells in
  `frameBack ⊖ frameFront` (outer patch: 1 own cell *outside* the frame; inner patch:
  1 own cell *inside* the frame, i.e. the shrunk ring). Same geometric band where the
  fluid buffer lives, by construction.
- The init script lays an own-dp wall lattice over the band by clipping its regular wall
  generator against the band frames (`_frame_and_band` mirrors
  `MultiresolutionBoundary::initZones`), so the ghost lattice lands exactly on the wall
  lines the neighbor owns resolution-wise differently — the wall is closed at the seam at
  the owning set's own resolution.
- Interface indexing is fixed by the C++ side (interfaces enumerated own-major over the
  topology chain links); the init script mirrors the same order when numbering the
  `boundary-ghost-buffer-<p>` files.

## 4. Agreed data flow

1. **Init (once, solver side):**
   - For each directed interface (own → neighbor) with `boundary-ghost-buffer-<p>-n > 0`,
     read the pre-generated lattice into a temporary boundary set and append
     (`r`, `rho`, `v`, `marker`, `n`, `elementSize`) at the **tail of the own boundary
     set** (`boundary[own]`). The VTK input carries no values for `drho`, `p`, `a` and
     `gamma`; those start at zero instead of copying uninitialized memory.
     `numberOfGhostParticles` and `ghostBegin` are recorded per interface.
   - Allocation: boundary allocations (`boundary_n_allocated`) must absorb the ghosts; a
     hard runtime error points at the allocation factor otherwise.
   - Ghost slots are addressed per step through a referential-index inverse
     (`ghostIndexInverseOwn`), so the mapping survives the boundary sorting performed by
     the neighbor search at step 0.
2. **Every step, inside `interact()` (`SolverMultiSetBlockMultiresolution`):**
   - **Phase 1 — boundary updates (unchanged):** `model.updateSolidBoundary(fluid_i,
     boundary_i)` + `model.finalizeBoundaryInteraction(...)` for all sets.
   - **Phase 2 — ghost value refresh:** for each interface, set `rho`/`gamma` of ghost
     slots by the selected method: MFD interpolation from the *source boundary* or
     direct-from-source accumulation from the *source fluid*.
   - **Phase 3 — interactions (unchanged):** `model.interaction(fluid_i, boundary_i)`
     and `model.interactionWithOpenBoundary(fluid_i, patches...)`. The merged boundary
     set (own wall + ghosts) is treated uniformly — no extra fluid sweep, no zone
     plumbing.
3. **`multiresolutionUpdate()`** is *not* involved with ghost values (it is the
   fluid–fluid coupling, after `integrate`); ghost value refresh must happen in the same
   step's `interact()` or the wall forcing would be one step stale.

## 5. Why these semantics

- **Boundary values are properties of the neighboring subdomain**, not of the own fluid:
  evaluating a ghost against the own fluid would be circular (the own wall set already
  covers the own-fluid side of the seam) and would erase exactly the shared boundary
  state the ghost exists to represent. Both methods therefore sample the *source*
  subdomain — its processed boundary state (interpolation) or its fluid state evaluated
  as if the ghost were part of the source's wall (direct-from-source).
- **Empty support must not blow up.** Interpolation keeps the previous value (the wall
  state changes slowly); direct-from-source produces the dry-wall state (`rho = gamma = 0`),
  the same values a regular boundary slot carries far from fluid.
- For BC types that require no per-step boundary update, the refresh pass is a no-op by
  construction of the methods (nothing to interpolate or accumulate from).

## 7. Implementation notes

- Both refreshes live on the model as `WCSPH_BI::updateGhostBoundaryInterpolated` and
  `WCSPH_BI::updateGhostBoundaryDirectFromSource`; the solver only dispatches. The
  `direct-from-source` refresh **mirrors `WCSPH_BI::updateSolidBoundary` and
  `finalizeBoundaryInteraction`** on the ghost slots with the source fluid as the
  neighbor set: same pair terms (`Σ W·m` / `Σ 2W·m` by `BCType::renormalize`, `Σ W·m/ρ`),
  same finalization. Any change to the model's boundary treatment must be mirrored here;
  the code carries a forward-pointer comment at the branch.
- The model functions themselves cannot be called for this — their loops span the whole
  boundary set and would overwrite the own-wall values with source-fluid sums.
- Device-lambda note: nvcc rejects `if constexpr` with first-capture of surrounding
  variables in extended lambdas; the renormalize dispatch is expressed as constant-folded
  arithmetic instead.
- Observed coverage: the interpolation samples the source *boundary lattice*, which is
  co-located with the ghost band, so every generated ghost position gets support once
  fluid is near. The direct-from-source samples the source *fluid*: support appears when and
  where that fluid actually reaches the band (verified at the wetted bottom seams), while
  pieces the source fluid never occupies (e.g. wall fragments far outside the source
  set's fluid box) keep dry-wall zeros — the pre-ghost behavior at those exact spots.

## 8. Safety notes verified in code

- `SolverMultiSetBase::removeParticlesOutOfDomain()` loops `fluidSets` only — boundary
  ghosts are not at risk in the block (non-MPI) path. `resetOverlaps()` calls it on
  `boundarySets` too, but that is the MPI/distributed path, unused by these cases
  (re-guard if enabled later).
- `updateSolidBoundary`'s `Particles::forAll` skips overlap-ring particles — ghosts in
  the ring are automatically excluded from the own-fluid evaluation ✅ (needed by design).
- Ghost slots are re-resolved every step through the referential-index inverse, so the
  slot mapping is immune to the boundary sorting performed by the neighbor search.

## 9. Limitations / watch points

- **Moving walls** are out of scope (ghosts are static at init); re-validation needed if
  a case with moving boundaries is used.
- Source values are computed from the *source subdomain's* data; where the source fluid
  is absent or retreating, the methods degrade to dry/stale wall values — benign in the
  2D verification, but corner values during transients deserve a look per case.
- The direct-from-source method cannot see past the source fluid's reach (see §7); where the
  ghost band was meant to cover a wall the source fluid never touches, use `interpolation`.
- VTK output of `boundary_*` files will include ghost particles (duplicates along seams)
  — cosmetic.

## 10. Verification

1. **2D 3-zone dam break (t = 1.0), `interpolation`:** identical 315072 steps as the
   removed copy variant and the ghost-free reference; final mass 178.376 (copy 178.105,
   reference 178.17); water-level sensor RMS ≤ 1.3 mm against both; zero NaN; ghost-tail
   values graded and physical across the wetted seams.
2. **2D 3-zone dam break (t = 1.0), `direct-from-source`:** identical 315072 steps, zero
   NaN; final mass 178.182 — the closest to the ghost-free reference of the three
   variants (Δ = +0.012 vs +0.206 interpolation, −0.065 copy), with more mass spread into
   the refined zones (L1 +0.62, L2 −0.46 against the reference); water-level sensor RMS
   ≤ 1.4 mm against interpolation, copy and reference; ghost tails physical and NaN-free
   at t = 0.9 (gamma up to 0.77 at the wetted wall pieces).
3. **3D 2-zone regression (t = 2.0)** ran on the removed copy variant; the 3D example has
   no ghost files after the removal (pre-ghost behavior) until a 3D band generator exists.
4. Allocation asserts never fire; no CUDA errors; refresh cost two small kernels per
   interface per step.
